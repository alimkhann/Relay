Phase 0.5: Dashboard Auth Fix (CRITICAL BUG)
Priority: Immediate | Effort: 1 hour | Risk: Low (rename + config)
Root cause discovered: The middleware file at apps/web/src/proxy.ts is named proxy.ts instead of middleware.ts. Next.js requires exactly middleware.ts — so the Neon Auth middleware never runs. Consequences:
- Session data cache cookie (5-min TTL) is never refreshed by middleware
- After ~5 minutes, every page load does a cold session fetch from Neon Auth server
- If that fails (network latency, token expired), user bounces to sign-in
- CLI auth confirmation also fails because /api/cli/auth/confirm needs a valid web session
Fix:
1. Rename apps/web/src/proxy.ts → apps/web/src/middleware.ts
2. Rename apps/web/src/proxy.test.ts → apps/web/src/middleware.test.ts
3. Update test import from "./proxy" to "./middleware"
4. Increase session data TTL from 5 min to 1 hour in apps/web/src/lib/auth/server.ts:
      sessionDataTtl: 3600  // 1 hour instead of default 300s
   5. Verify on local dev and production
Files: apps/web/src/proxy.ts, apps/web/src/proxy.test.ts, apps/web/src/lib/auth/server.ts

Phase 1: Capture Pipeline Dedup (5 Gaps)
Priority: Critical | Effort: 3-4 days | Risk: Medium
Gap 1: Service Worker Signature Reset
File: apps/extension/src/background/index.ts (line 707)
Root cause: lastCapturedSignature is in-memory only, resets when MV3 worker suspends (~30s).
Fix: Persist per-tab signatures to chrome.storage.session. On worker wake, rehydrate before first capture decision.
Changes:
- Add persistTabSignature(tabId, signature) / getTabSignature(tabId) helpers
- Replace direct assignment with storage-backed version
- Cleanup on tab close
Gap 2: Archived Sessions Bypass Dedup
File: packages/db/src/repositories/session-repository.ts (line 64)
Root cause: getLatestComparable() WHERE clause includes is_archived = false.
Fix: Remove is_archived = false filter. Dedup should work regardless of archive status.
Gap 3: Page Fingerprint Drift
File: packages/db/src/repositories/session-repository.ts (line 64)
Root cause: pageFingerprint in comparable key. DOM changes shift fingerprint.
Fix: Use (project_id, platform, normalized_url) as primary key. Fingerprint becomes optional secondary signal.
Gap 4: Weak Client Hash, No Server Verification
Files: apps/extension/static/relay-content.js, apps/web/src/server/services/capture-service.ts
Fix: Server computes SHA-256 of extracted_text. Reject if identical hash within 15-min window using existing capture_signature index.
Gap 5: mergeGovernedList Near-Dupe Accumulation
File: packages/shared/src/utils/merge-governed.ts (line 60)
Fix: Two-layer approach:
1. Raise isSameTopic() threshold from 60% → 85% for the fast path
2. Items scoring 60-85% get batched for LLM dedup (new packages/shared/src/utils/llm-dedup.ts)
3. Export configurable thresholds: MERGE_THRESHOLD_HIGH = 0.85, MERGE_THRESHOLD_GREY = 0.6
Dashboard Chats Count Fix (alongside Phase 1)
File: packages/db/src/queries/dashboard-queries.ts, packages/db/src/repositories/session-repository.ts
Problem: totalChats counts source_sessions.length — duplicate sessions from re-capture inflate this.
Fix: Count by DISTINCT source_conversation_id (or DISTINCT (platform, url) when conversation ID is null). This gives the real number of unique chats.
Testing: New tests in merge-governed.test.ts for grey zone + capture-dedup.test.ts for each gap.

Phase 1.5: Capture Completeness (MAIN World Fetch Interception)
Priority: High | Effort: 5-6 days | Risk: Medium-High (new architecture)
Problem: Current capture is 100% DOM-based. Virtual scrolling means only ~15-30 messages exist in DOM. Long conversations lose 20-80% of content.
Solution: Inject a MAIN world content script that wraps window.fetch before each AI site's app loads. Intercept full conversation API responses.
Architecture:
MAIN World Script (document_start)
  → Wraps window.fetch / XHR
  → Filters by platform URL patterns
  → Parses response JSON / SSE streams
  → Posts structured data to ISOLATED world via window.postMessage
ISOLATED World Content Script (existing)
  → Receives network-captured conversation
  → Falls back to DOM scraping if no network data
  → Merges / deduplicates turn data
  → Sends to background via chrome.runtime
Per-platform API endpoints:
- ChatGPT: GET /backend-api/conversation/{id} — full conversation with all messages in mapping object
- Claude: GET /api/organizations/{org}/chat_conversations/{id} — full chat_messages array
- Perplexity: REST + WebSocket combo for thread data
Implementation sequence:
1. New Plasmo content script: apps/extension/contents/network-intercept.ts with world: "MAIN", run_at: "document_start"
2. Start with ChatGPT only (best documented API)
3. Add captureSource field to ParsedTurn: 'dom' | 'network' | 'merged'
4. Bridge to existing content script via window.postMessage
5. Merge logic: prefer network for content completeness, DOM for formatting
6. Extend to Claude, then Perplexity
7. Add completeness verification: compare turn count from network vs DOM
8. Add telemetry: capture_source, turn_count_mismatch
Files:
- New: apps/extension/contents/network-intercept.ts — MAIN world fetch wrapper
- New: apps/extension/src/capture/network-parsers/chatgpt.ts — ChatGPT API response parser
- New: apps/extension/src/capture/network-parsers/claude.ts — Claude API response parser
- New: apps/extension/src/capture/network-parsers/perplexity.ts — Perplexity response parser
- Modified: apps/extension/static/relay-content.js — add window.postMessage listener, merge logic
- Modified: packages/adapters/src/base/dom-utils.ts — add captureSource field to ParsedTurn
