Relay Autonomous Context Plan for Claude Opus 4.6

Purpose
- Continue the non-frontend implementation of Relay as a cross-surface truth maintenance layer.
- Browser captures, MCP sessions, CLI sessions, and future extension thread-state should converge on one canonical continuity system.
- This document assumes recent implementation work already added a first pass of:
  - work session tables/repositories
  - MCP auto-open / checkpoint / close session lifecycle
  - work-session checkpoints feeding the brief/bootstrap path
  - truth-weighted memory conflict scoring beyond freshness-only resolution

What was implemented in the current round
1. First-class work-session model
- Added DB migration `packages/db/neon/migrations/0016_work_sessions.sql`
- Added tables:
  - `work_sessions`
  - `work_session_events`
  - `work_session_checkpoints`
- Added repositories/mappers/types for all three.

2. Autonomous MCP session lifecycle
- MCP client now auto-opens a work session when project-scoped tools are used.
- MCP client stores the session's base sync mark and uses it as default `since` for `relay_get_brief` when the caller does not supply one.
- MCP client now logs lightweight read events and writes checkpoints on meaningful mutations.
- `relay_save_context` now closes the work session after persisting.
- Shutdown hooks attempt to close the active session on process termination.

3. Canonical brief integration
- Recent MCP/CLI work-session checkpoints are transformed into synthetic memory-like items during bootstrap generation.
- Those synthetic items influence effective project state and recent progress.
- Browser digest persistence also writes work-session events/checkpoints so browser-originated state now enters the same generic session substrate.

4. Truth scoring beyond freshness
- Shared merge logic now scores memory items by:
  - explicit pinning
  - authority
  - durability
  - validation state
  - evidence kind
  - reaffirmation count
  - session importance
  - finalization state
  - recency as a tie-breaker / small factor, not sole driver
- `buildEffectiveProjectState` now deduplicates and orders memory-derived context using this score.

5. Supporting product changes already live
- Landing/auth domain updated to `https://onrelay.app`
- Landing preloader and sign-in background fixes were completed
- Random landing background + opposite CTA image pairing implemented

Important implementation constraints going forward
- Do not regress to freshness-only truth resolution.
- Do not create a second canonical continuity system parallel to `project_state` + `bootstrap_packets`.
- Prefer append-only event/checkpoint storage + derived materializations.
- Avoid polluting `memory_items` with every MCP/browser event. Durable truth should remain curated.
- Extension should stay a quiet assistant, not a control panel.

Current architecture after this round
Canonical continuity layers:
1. Raw capture / source sessions / turns / tool events
2. Work sessions + work session events + work session checkpoints
3. Durable project truth (`project_state`, curated memory, overrides)
4. Materialized continuity outputs (`bootstrap_packets`, future delta briefs / handoffs)

Work still needed next (highest priority)

Phase A — Harden work-session lifecycle quality
Goal
- Make work sessions reliable, low-noise, and fully useful for continuity.

Tasks
- Add stale-session sweeper / stale-session recovery policy
  - mark sessions stale after inactivity threshold
  - allow resume vs replace logic when a new client session starts
- Refine session reuse criteria
  - surface
  - workspace path
  - thread ID
  - client/agent identity
  - inactivity window
- Add explicit `last_used_at` equivalent behavior for work sessions
- Add tests for open/reuse/close semantics

Recommended files
- `apps/web/src/server/services/work-session-service.ts`
- `packages/db/src/repositories/work-session-repository.ts`
- new tests in `apps/web/src/server/services/` and/or `packages/db/src/repositories/`

Phase B — Make delta continuity truly automatic
Problem
- The MCP client now uses `baseSyncMarkAt` as default `since`, but the system still needs stronger server-side guarantees and user-surface semantics.

Tasks
- Add first-class “since last sync” mode to bootstrap generation and API responses
- Surface grouped deltas by type:
  - decisions
  - tasks
  - constraints
  - recent progress
  - conflicts
  - important notes
- Ensure sync marks only advance on successful brief delivery
- Consider separate read checkpoints vs sync marks if needed

Recommended files
- `apps/web/src/server/services/bootstrap-service.ts`
- `apps/web/src/server/services/sync-mark-service.ts`
- `packages/mcp/src/tools/get-brief.ts`
- project bootstrap routes

Phase C — Browser/extension thread-state promotion
Problem
- Browser digests now emit work-session checkpoints, but promotion rules are still basic and browser state is not clearly separated as thread-scoped vs project-scoped truth.

Tasks
- Add explicit thread-state vs project-truth distinction
- Track association confidence and routing source more explicitly
- Promote browser thread observations to project truth only when durable enough
- Keep foundational older truth from being overwritten by later-captured but weaker browser observations
- Add browser/extension-side diagnostics when association confidence is weak

Recommended files
- `apps/web/src/server/services/capture-service.ts`
- `apps/web/src/server/services/digest-service.ts`
- extension background/routing/storage files
- shared merge/reconciliation utilities

Phase D — Provenance / conflict / validation model completion
Problem

Tasks
- Extend durable items with stronger metadata where needed:
  - source session ID
  - source thread ID
  - validation state
  - conflict state
  - supersession lineage
- Add explicit conflict storage / surfacing rules when contradictory items should coexist
- Add validation/reconciliation pass for unsupported or weak session summaries
- Add quality scoring tests for foundational-vs-newer conflicts across surfaces

Recommended files

- `apps/web/src/server/services/context-reconciliation-service.ts`
