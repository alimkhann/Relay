# Relay positioning and investor-worthiness assessment

Date: 2026-04-13
Status: candid founder note

## Best positioning

Relay is not best described as:
- chat memory
- generic RAG
- another AI wrapper

Relay is best described as:
- the trusted continuity layer between browser AI chats and coding agents
- the project canon / project truth manager for AI-native work

## Why the project is real

- there is real user pain: context gets lost across tools and sessions
- the product is differentiated by cross-surface continuity
- the architecture is now materially better than a thin wrapper

## What still needs to be true for commercial success

- users must trust it
- onboarding must be simple
- the UI must explain truth, conflicts, and provenance clearly
- free tier must stay economically safe

## Investor-worthiness - honest take

### Strengths
- real problem
- strong product wedge
- backend architecture now has real depth
- better-than-average technical/product thinking for a solo founder project
- a believable route to sticky utility behavior

### Risks
- category still needs clear storytelling
- UI and docs must catch up to backend depth
- platform reliability issues like MCP 429 can erode trust
- solo founder execution bandwidth is the main bottleneck
- growth is not guaranteed just because the pain is real

## Bottom line

Relay is not obviously nonsense.
It is plausibly fundable if:
- users actually depend on it
- retention and paid conversion appear
- the product narrative becomes sharp
- trust UX catches up

It is too early to assume a venture-scale outcome, but it is absolutely reasonable to keep pushing.
